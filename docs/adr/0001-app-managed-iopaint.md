# Let the app manage IOPaint

Status: Superseded by ADR 0003.

The application owns the lifecycle of the local IOPaint process instead of requiring the user to start it separately. It starts IOPaint lazily on the first cleanup request, checks that the service is ready, reuses the process for the rest of the session, and stops only the process it started when the app exits. The runtime defaults are executable `iopaint`, model `lama`, device `cpu`, and preferred port `8080`, while Settings may override each value without storing them in the project. If the preferred port is occupied, the app leaves the other process untouched and launches its own IOPaint process on an available local port. IOPaint is the default explicit cleanup method for a selected block and the current page; page cleanup runs blocks sequentially with progress and cancellation, and one failed block does not stop the remaining blocks. This keeps local cleanup available by default without adding startup cost to sessions that do not use it. If startup, readiness, or cleanup fails, the app reports the error without overwriting the existing image or silently falling back, then lets the user choose an existing cleanup method.
